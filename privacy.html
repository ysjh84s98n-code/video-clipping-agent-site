Privacy Policy

Video-Clipping-Agent · Google Drive & Google Docs integration

Effective date: 15 November 2026

This policy explains how the current Video-Clipping-Agent Google integration accesses and handles Google user data. The project is maintained by the GitHub account ysjh84s98n-code. It is a self-managed desktop/cloud integration: you control the computer or cloud environment where it runs.

This public website is informational. It does not accept Google credentials, authorize your Google account, receive OAuth callbacks, or process your documents or videos.

1. Google data we access

The integration requests only https://www.googleapis.com/auth/drive.file. This scope permits viewing and managing files that you explicitly select or open for the app, or that the app creates. It does not grant access to all files in your Google Drive.

For the current workflow, the integration accesses:

  • The Google document you select, including its text, hyperlinks, tabs and nested content, to extract source links.
  • The IDs and metadata of the selected document and destination folder, including file type, access status and the ability to add files to the folder.
  • The finished MP4 files that you instruct the integration to upload, and the metadata of the files it creates in the selected Google Drive folder.
  • OAuth authorization credentials, including access and refresh tokens, needed to carry out your authorized requests.

The integration does not request Gmail, Contacts, or full-Drive scopes. Selecting a folder does not automatically grant access to all pre-existing files inside it.

2. How Google data is used

Google data is used to read source links from your selected document, check access to your selected destination, upload finished clips, and maintain the connection you authorized. Access tokens are refreshed so that a cloud deployment can run without repeated browser sign-in while the refresh token remains valid.

The Google integration does not use Google data for advertising, profiling or sale. It does not send Google data to generative AI services or use it to train generalized AI or machine-learning models. If you add separate tools to your video workflow, their data handling is outside this integration and must be reviewed separately.

3. Storage and security

During initial setup on Windows, OAuth credentials are encrypted using Windows DPAPI for the current Windows user and stored outside the project repository. Access tokens are held in memory. The local Google Picker page receives only a short-lived access token; it does not receive the refresh token or OAuth Client Secret.

For a cloud deployment, credentials and selected file IDs are exported in a password-encrypted AES-256-GCM bundle using a Scrypt-derived key. The password is supplied through the cloud operator’s secret manager or a private mounted secret file. Decryption takes place in the process that runs the integration.

Document content is read into runtime memory. The command-line program can print extracted links and upload result metadata to standard output; your terminal, scheduler or hosting platform may retain that output in logs. The operator is responsible for restricting access to its runtime, secret store, logs and backups.

Your source document and uploaded clips remain in your Google Drive. This integration does not maintain a separate centralized database of Google account users or Google document contents. No security measure can guarantee absolute protection.

4. Sharing and disclosure

The integration sends authorized API requests and clip uploads to Google. When you deploy it in a cloud environment, your chosen infrastructure provider may process data and credentials as part of running that environment under your configuration. This public website does not receive those credentials or files.

We do not sell or share Google user data with advertisers or data brokers. The integration does not provide a feature for third parties to browse your Google files. Anyone to whom you grant access to your deployment or its logs may be able to access the information it handles.

Video-Clipping-Agent’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

5. Retention, deletion and revoking access

OAuth credentials and selected file IDs remain in your local encrypted store or cloud bundle until you remove or replace them. Extracted links retained in logs remain subject to your operator’s log-retention settings. Documents and uploaded clips remain in Google Drive until you delete them there.

  1. Stop any running or scheduled instances of the integration.
  2. Open Google Account → Third-party connections, select Video-Clipping-Agent and remove its access. This prevents further authorized Google API access.
  3. Remove the local DPAPI credential file, cloud credential bundle, password secret, and any retained outputs or backups you control. The local store is %LOCALAPPDATA%\video-clipping-agent\oauth.dpapi; the exported bundle is normally cloud.vca in the same folder.
  4. If you also want to delete documents or uploaded clips, delete them in Google Drive and manage the Drive trash according to your needs.

Revoking the app’s access does not itself delete your Google Drive files or copies of outputs in your own logs and backups.

6. This public website

The site consists of static pages. It does not use advertising, analytics scripts, tracking pixels, third-party fonts, cookies or browser storage set by this site. GitHub Pages, which hosts these pages, may process network information such as your IP address and request metadata to deliver and secure the site. See the GitHub Privacy Statement.

External links take you to services with their own privacy policies. The Google Picker used during desktop authorization is separate from this informational website.

7. Contact and data requests

For privacy questions, corrections or help with deleting data, contact the project maintainer through the public website repository’s GitHub Issues. If your request involves personal or confidential information, ask for a private contact channel without including those details in a public issue.

Do not post OAuth codes, API keys, passwords, tokens, private document contents or video files. The maintainer cannot directly delete files or secrets in an environment you operate; the deletion steps above explain how you can remove them.

8. Changes to this policy

Material changes to the integration’s data handling will be reflected on this page with an updated effective date. Additional Google permissions, if ever needed, require a separate authorization request.
